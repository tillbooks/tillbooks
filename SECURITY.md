# Security policy

## Supported versions

TILL is pre-alpha. There is no support window yet, and there are no releases to back-port to.
Security fixes land on `develop`. Run current code, and do not run TILL against books you cannot
afford to lose.

## Reporting a vulnerability

Report security issues privately. Do not open a public issue for a vulnerability.

- Email **security@tillbooks.ch**.
- Once the repository is public you can also open a private security advisory on GitHub.

Tell us what you found, how to reproduce it, and what an attacker gets out of it. A proof of concept
helps. You will get an acknowledgement, and we will tell you honestly whether and when we can fix it.
We are a small team working part time: we would rather say "not soon" than go quiet on you.

Please give us a reasonable window to ship a fix before you publish.

## What we care about most

TILL keeps books. The things that would hurt a user worst, roughly in order:

1. **Anything that mutates a posted entry.** Posted entries are append-only and immutable by design.
   A correction is a reversing entry. A bug that edits or deletes history is the most serious class
   of defect in this codebase, above crashes and above data loss.
2. **Anything that breaks idempotent posting**, so a retry double-counts money.
3. **Anything that leaks the ledger off the machine.** TILL is local-first. Books live in a SQLite
   file on the user's own hardware and are meant to stay there.
4. **Anything that lets the MCP surface do what the human interface forbids.** The agent and the
   GUI ride the same engine verbs on purpose. A gap between them is a bug.
5. Rounding or currency handling that silently loses money. Money is integer Rappen at the bottom of
   the path. A float that reaches the ledger is a defect, not a rounding preference.

## Out of scope

- Attacks that need physical access to an unlocked machine that already holds the books.
- Missing hardening on a local-only, single-user surface with no listener exposed to a network.
- Reports generated by a scanner with no reproduction and no described impact.
